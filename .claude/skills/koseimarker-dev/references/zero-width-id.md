# ゼロ幅一意ID コーデック仕様と変更手順

この拡張が作ったマーカー（＝所有マーカー）を、ユーザーから見えない形で識別するための仕組み。
**誤判定は「他人のマーカーを消す」に直結する**ため、判定は徹底して厳しい側に倒してある。読まずに緩めないこと。

実装は3か所に分散していて、規則が一致していることが前提になっている:

| 場所 | 役割 |
|---|---|
| `js/parser.js` の `encodeId` / `decodeId` / `_parseTag` | パネル(UI)側の符号化・復号 |
| `js/hostscript.jsx` の `_encodeId` / `_decodeId` | ExtendScript(Premiere)側の符号化・復号 |
| `tests/parser.test.js` | タグを手組みして境界を検証（`SIG` / `cksum()` を自前で持つ） |

## タグ構造

name の**末尾**に付く（先頭ではない。「校正✅」プレフィックスを付け外ししても消えないのはこのため）。

```
FRAME + SIG + FRAME + runIdBits + FRAME + kBits + FRAME + checksumBits + FRAME
```

| 記号 | 文字 | 意味 |
|---|---|---|
| FRAME | `U+2060` WORD JOINER | 区切り（センチネル） |
| 0 bit | `U+200B` ZWSP | ビット0 |
| 1 bit | `U+200C` ZWNJ | ビット1 |

- `KMID_SIG = 11001010111100001101`（名前空間シグネチャ）
- `KMID_CKP = 1000003`（素数。積が 2^53 未満に収まるよう選定）
- checksum = `(runId%P * 31 + k%P * 17 + 12345) % P`
- 数値は**正準**2進（MSB先頭・先頭ゼロ埋めなし・0は `"0"`）。
- ID は `(runId, k)` の2要素を別フィールドで持つ。`runId*1000+k` のような掛け算で潰すと衝突する。復号値は正準文字列 `"runId:k"`。

## 所有と判定する条件（全部満たしたときだけ）

1. 末尾のゼロ幅ランを切り出し、`split(FRAME)` がちょうど6要素で両端が空（＝センチネル構造が正しい）
2. シグネチャが `KMID_SIG` と完全一致
3. 各フィールドがゼロ幅0/1のみで構成され、空でない
4. 正準表現である（先頭ゼロ埋めを拒否／復号値を再エンコードして元のビット列と完全一致）
5. 復号値が 2^53-1 以下
6. チェックサムが一致

**形だけの一致は非所有**として扱う。ticks による代替特定は禁止（同一 ticks の取り違えで別マーカーを消す）。
非所有マーカー（旧形式・他ツール・手打ち）は idx＋ticks の二重キーで扱う——所有マーカーとは別系統であることを混ぜない。

## ビット演算を使わない理由

ExtendScript も含め、`|` `<<` などのビット演算は32bit幅で溢れる。runId は `Date.now()` 由来で 2^32 を超えるため、
復号は**乗算**（`val = val * 2 + bit`）で行い 2^53 まで正確に扱う。ここを「ビット演算の方が速い」と書き換えると静かに壊れる。

## 変更するときの手順

コーデック規則（SIG／チェックサム式／構造／文字の割り当て）を変える場合:

1. `js/parser.js`、`js/hostscript.jsx`、`tests/parser.test.js` の**3つを同じコミットで**更新する。1つでも取り残すと、パネルが自分のマーカーを認識できなくなる。
2. `node .claude/hooks/km-invariants.js` で3点同期を確認する（定数・チェックサム係数・ゼロ幅文字の割り当てを機械的に照合する）。
3. `node tests/parser.test.js` と `node tests/host.test.js` を両方通す。
4. **既存マーカーとの互換性を必ず検討する**。SIG を変えると、旧SIGで打たれた既存マーカーは非所有になる＝一覧から消え、`clearFirst` でも消せなくなる。移行が要るなら旧SIGを読み取り専用で受理する経路を用意すること。互換を切るなら、その判断を `docs/notes/` に残す。

## 変更してはいけない前提

- タグは name の**末尾**（プレフィックス操作と衝突させない）。
- 使う文字は表示幅ゼロのものだけ（可視文字を混ぜるとユーザーのマーカー名が汚れる）。
- 判定の各条件を「実用上まず起きない」を理由に省かない。省いた分だけ誤削除の確率が上がる。
