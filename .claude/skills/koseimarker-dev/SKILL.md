# KoseiMarker 改修ガイド

このパネルは校正リスト（添削指示書 .md / typo-check レポート表）を読み、Premiere のシーケンスマーカーを一括生成する。
**壊れると実害が出るのは「ユーザーの既存マーカーを消す」経路**なので、そこを守る作りになっている。改修時はまずその設計意図を理解してから触ること。

## 1. どのファイルを触ったら何を検証するか

| 触ったファイル | 必ず走らせるもの |
|---|---|
| `js/parser.js` | `node tests/parser.test.js` ＋ `node .claude/hooks/km-invariants.js` |
| `js/hostscript.jsx` | `node tests/host.test.js` ＋ `node tests/parser.test.js` ＋ `node .claude/hooks/km-invariants.js` |
| ゼロ幅IDコーデック（上記2ファイルの KMID_* 周辺） | 上記全部。加えて `tests/parser.test.js` 側の定数も**同時に**直す |
| `js/main.js` | 両テスト（UI経由の呼び出し規約が変わっていないか） |
| `tests/*.test.js` | 両テスト |

`.claude/hooks/` のフックが編集直後と完了前に自動で回すが、**自動チェックがあることを理由に自分で確認しないのは禁止**。フックは網ではなく保険。

自動チェックが拾えるのは「テストの失敗」と「コーデック定数の3点ズレ・ES3違反」だけ。
**拾えないもの**＝Premiere 実機での挙動、マーカーの色、CEPのキャッシュ問題、UI操作の流れ。ここは人間の確認が要る（§5）。

## 2. 改修の型

1. **どの層の問題か切り分ける**。TC文字列の解釈 → `parser.js`／マーカーの読み書き → `hostscript.jsx`／画面と操作 → `main.js`。層をまたぐ修正は、まず「どちらが権威か」を決めてから書く。
2. **先にテストを足す**。この repo のテストは node だけで動く手書きアサーション（外部依存ゼロ）。既存の書き方に合わせて追加する。
3. 実装する。
4. 両テスト＋不変条件チェックを走らせ、**全PASSにしてから完了とする**。落ちたまま「あとは実機で」は不可。

## 3. 触るときに壊しやすい不変条件

### replaceMarkers の順序（K3-1）
`js/hostscript.jsx` の `replaceMarkers()` は **①事前検証 → ②追加 → ③追加が全件成功したときだけ削除** の順。
追加が1件でも失敗したら旧マーカーは消さない。**一時的な重複は再実行で直せるが、消えたマーカーは戻らない**という非対称性がこの順序の理由。
- 削除と追加を別の `evalScript` に分割しない（途中で失敗すると片方だけ適用される）。
- 「先に消してから入れる方が素直」に見えても戻さない。
- `clearFirst` の削除対象は追加前スナップショットに限定する（今回追加した rid を巻き込まない）。

### ゼロ幅一意ID
所有マーカーの判定は name 末尾のゼロ幅タグ。**形が似ているだけのマーカーを所有と誤判定すると、他人のマーカーを消す**。
判定は「センチネル構造＋シグネチャ一致＋チェックサム検証OK＋正準表現」を全部満たしたときのみ。ticks へのフォールバックは禁止。
詳細と変更手順は `references/zero-width-id.md` を読むこと（コーデックに手を入れるなら必読）。

### タイムコードと微調整プリセット
微調整プリセット（30系10f／60系30f）は**秒精度TCにだけ**適用する。フレーム精度・ミリ秒精度のTCは補正しない——これは恒久仕様であって未実装ではない。「全部に適用した方が一貫する」は誤り。
秒精度TCとSRT形式は「実時間」として実fpsで換算する（名目30コマ×秒で数えると29.97fpsでは10分で約18コマずれる）。

### ExtendScript(ES3) 制約
`js/hostscript.jsx` は ES3。`const`／`let`／アロー関数／テンプレート文字列／`JSON` は使えない。`var` と `function` のみ、JSONは手組み。
うっかり書いても node のテストは通ってしまい、**Premiere 上でだけ動かない**。不変条件チェックがこれを見る。

## 4. レビュー時に見る点

- 追加と削除の順序が入れ替わっていないか、別呼び出しに分割されていないか。
- 所有判定が緩められていないか（チェックサム検証の省略、ticks フォールバックの復活）。
- コーデック定数を変えたのに3ファイルのどれかが取り残されていないか。
- ES3 違反が `hostscript.jsx` に混ざっていないか。
- 秒精度TC以外に補正が入っていないか。
- 新しいエラー経路で、失敗しているのに成功扱いで返していないか。

## 5. node のテストで届かない範囲

インストールは**シンボリックリンク方式**（`~/Library/Application Support/Adobe/CEP/extensions/KoseiMarker` → repo 本体）。この repo を直接編集すれば実機に反映される＝コピーを作らない。
コード更新後は Premiere の再起動が必要。効かないときは CEP キャッシュ `~/Library/Caches/CSXS/cep_cache` を削除する。
実機で見るべきは、マーカーの色（校正=赤／✅済=緑）、一覧の並びとジャンプ、件数表示、削除の巻き込みが無いこと。

## 6. リモート（Claude Code on the web）で作業している場合

`dev-team` スキルと `~/DECISIONS.md` / `~/PENDING.md` はローカル Mac にしかない。リモートセッションではそれらを前提にした手順は実行できないので、
本格改修では代わりに `/code-review`（必要に応じて `/security-review`）＋本ガイドの検証を通す。判断の記録が要る変更は、ローカルへ持ち帰る前提で PR 本文か `docs/notes/` に残す。
